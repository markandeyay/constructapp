# WP-07: web surfaces

Owner: wp07-web. Branch: feat/web. Spec section 10, governed by section 16.

## Patterns followed

All in `apps/web`, no new dependency, no new design tokens.

- Layout shell, header, tools strip, chat panel: `app/page.tsx` (unchanged structure). The selector sits at the top of the Conversation panel, above the thread, and swaps the composer.
- Surfaces and type: the same Tailwind tokens as `components/plasmid-map-view.tsx` (`rounded-md border border-line bg-paper p-md shadow-raised`, `text-caption uppercase tracking-[0.06em] text-slate` captions, `font-serif text-h3` headings, coral primary button, sage/honey/clay severity colours).
- Empty state: same dashed `bg-mist` card as the plasmid map.
- Feature colours: the AAV map reuses `lib/component-colors.ts` through a role to feature type map.
- Export buttons: `components/capability-exports.tsx` mirrors the `ExportActions` markup and classes.
- The conversational loop, evidence panels and plasmid exports are untouched. For the three new capabilities each design appends a user line and an assistant result line (with the shared validation report) to the same thread.

- `e2e/capabilities.spec.ts` plus `e2e/fixtures/*.json` (real API responses, all routes mocked, deterministic).

## Result panels

- Plasmid: existing circular seqviz map, unchanged.
- AAV (`AavResultPanel`): SVG linear cassette from `artifacts.linear_map_json` (falls back to the length budget rows), elements drawn to scale on an axis that extends to the hard limit, ITR arrowheads pointing at each other, dashed markers for target, soft and hard limit, hatched span beyond the target. Then the length budget table (element, bp, running total with a meter, headroom to target, total row, limit basis text), the remediation options computed by the backend with an "Apply this change and recompose" button that sets the promoter, polyA or WPRE choice and resubmits, composition notes, and `parameters_used`. The panel never renders the circular component; a test asserts there is no `seqviz-map` in AAV mode.
- Assembly (`AssemblyResultPanel`): junction map SVG (fragments, join labels, closing arc for circular), junction details, order table (select-all sequence cells, "Copy table" as TSV, "Export CSV" from `outputs.order_table_csv`), protocol, domestication report, `parameters_used`. The CSV comes from the design response, so `POST /v1/assembly/order-table.csv` is not called.
- gRNA (`GrnaResultPanel`): off-target statement, target sequence with complement line and guide bars above (forward) and below (reverse), score reference from `GET /v1/grna/reference`, ranked table with expandable per-guide reasoning, on-target and off-target detail, per-guide validation report, cloning oligos, unsearched guides, `parameters_used`.

## UNKNOWN versus PASS

`validation-report.tsx`. UNKNOWN is never colour only: the badge reads "? Not evaluated" (PASS reads a check mark and "PASS"), the row has a dashed border and a hatched background (PASS rows are solid and plain), the message is prefixed "Not evaluated.", the panel header shows a "N not evaluated" chip and a note saying a check that was not evaluated is not a pass and is excluded from the overall verdict. Rows carry `data-severity`. A test asserts the dashed versus solid border and the background image difference.

## Off-target statement, verbatim

Rendered by `OffTargetStatement` in `components/grna-panel.tsx` as one string from `off_target_space_statement` (top of the panel) and from each guide's `off_target.space_statement` (inside every expanded guide row). It is also appended to the chat result line (`outcomeSummary`). The export buttons download the API's `exports` strings unmodified, which begin with the statement. The UI adds no adjective and never says genome-wide except in the API's own negated sentence. The e2e test compares `textContent` of every rendered statement to the API field with strict equality, and compares the downloaded TSV to the API export.

The statement as rendered for the fixture request:

`Off-target search covered the target sequence only, 198 bp in total across 1 sequence. No delivery construct sequence was supplied, so self-targeting of the delivery construct was not searched. This is not a genome-wide search.`

Scores: every on-target cell shows the model name, its kind, and "Prediction from a published model, not a measurement" (or "Labeled heuristic, not a published score and not a measurement"). The off-target cell names the specificity model and says prediction, not a measurement. The expanded row shows the API `disclaimer`, validity domain and citation. A score outside the model's domain shows "No score".

## Notes and limits

- Refinement for the three new capabilities is by editing the form and resubmitting (and the AAV apply-change buttons). There is no natural-language refine endpoint for them.
- The outcome-report flow is plasmid only (its endpoint is keyed to plasmid designs); the strip says so for the other capabilities.
- AAV needs a pasted transgene CDS because the API has no resolver ("a placeholder sequence is not an option").
- Pre-existing quirk, not changed: the footer shows "Offline" whenever the status line is non-empty, which includes after a successful plasmid design.
- Brand grep over tracked and untracked files hits only `PROGRESS.md` and `progress/WP-03.md`, where earlier packages quote the grep command itself. No file authored here matches.
