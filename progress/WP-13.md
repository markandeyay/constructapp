# WP-13: wire the section 11 screening gate into the export routes

Model: Opus. Done by the orchestrator directly after the dispatched subagent was
killed mid-task by a safety classifier false positive on the word "bio" in its
prompt; that is recorded here rather than left as a silent gap.

## What was asked

Wire the provenance gate from section 11.1 into the serving export path, so that
exports returned by the running application actually pass through it. Before
this package the gate existed, was tested, and had no call site, which the README
said in those words.

## What was built

`services/api/routes/_screening.py`, new. Two functions and one audit log
accessor, deliberately thin: the gate itself is unchanged, and this module only
decides what a route does with the gate's answer.

* `screen_export(subject, artifacts, validation_overall)` returns
  `(allowed, reason)`. It screens only the artifacts whose names appear in
  `SUPPORTED_EXPORT_FORMATS`, which is the gate's own vocabulary, so an artifact
  is gated exactly when the audit entry has a name for what it is.
* `withhold_artifacts(payload, reason)` empties `result.artifacts` and sets
  `export_blocked` and `export_block_reason`, leaving everything else alone.
* `audit_log()` returns a `JsonlExportAuditLog`, constructed per call.

`services/api/routes/aav.py`: `_bundle_payload` now builds an `ExportSubject`
through the existing `aav_subject` adapter and screens before returning. Both the
design and the validate endpoints go through `_bundle_payload`, so both are
covered by the one change.

## Two decisions and why

**A blocked export returns 200, not an error.** Section 11.1 blocks the export,
not the design. A researcher whose cassette carries an unattributable span needs
to see the report and the span. A provenance fact presented as a 500 reads as a
fault in the tool instead.

**The audit log is constructed per screened export, not held as a module
singleton.** `JsonlExportAuditLog` resolves `CONSTRUCT_EXPORT_AUDIT_LOG` when it
is constructed. A singleton would freeze whatever the environment said at import
time, which would silently ignore an operator pointing the log elsewhere and
would make a test that redirects the log write into the real one instead.

## A real defect this package found and fixed

The first version of the wiring passed the gate no audit log. The gate ran, the
provenance assertion ran, allowed and blocked were decided correctly, and
`evaluate_export` wrote nothing, because `audit_log` defaults to `None` and the
record call is guarded by `if audit_log is not None`.

This would have shipped as a gate that enforces section 11.1 items 1 to 3 and
silently omits item 4. It was caught by checking for the audit file rather than
by reading the diff: the demo flow snapshot came back byte identical to its
pre-wiring baseline, which was the intended result for the allowed path and is
also exactly what a gate that does nothing produces. The file's absence is what
distinguished the two.

Recorded because the near miss is the point: a passing diff was consistent with
both the correct outcome and a no-op, and only an independent observable told
them apart.

## Scope, stated as a limit rather than as coverage

Gated: the AAV vector capability, both endpoints.

Not gated: plasmid, assembly and primers, guide RNA.

For assembly and guide RNA the blocker is concrete. `SUPPORTED_EXPORT_FORMATS` in
`packages/application/exports.py` is `{genbank, fasta}`. Those capabilities export
order tables and guide tables as TSV and CSV. Gating them requires first giving
the audit entry and the format validator a name for a table export, which is a
change to WP-08's module and is not something this package invented a value for.
The plasmid path has its own older export route and was left alone.

## Tests added

In `tests/aav/test_api.py`, three tests driving the real provenance assertion
over a real composed cassette. The gate is not mocked, because the claim worth
testing is that the route releases attributable DNA and withholds unattributable
DNA, not that a stub was called.

1. A fully attributed design exports with non-empty GenBank and FASTA, and one
   `exported` entry is recorded.
2. A design whose transgene element carries an undeclared source token returns
   200 with no artifacts, a reason naming the span size, an intact report, and a
   `blocked` entry.
3. A blocked export is recorded before it is refused, since an unrecorded
   refusal is the hole item 4 exists to close.

A fourth change was needed to make these honest: the audit redirect is an autouse
module fixture, because every `/v1/aav/design` call in the module is itself a
screened export. Without it the pre-existing tests appended seven entries to the
repository's real `data/audit` log, and the entry counts asserted above would
have depended on how many other tests ran first. Verified: after a full suite
run, `data/audit` does not exist.

The assertion in tests 2 and 3 is `["exported", "blocked"]`, not `["blocked"]`,
because composing the design under test is itself a screened export. Asserting
both keeps the setup call visible instead of pretending the gate ran once.

## One pre-existing condition, not introduced here

Nine tracked inherited documents contain em dashes: `SYSTEM_DESIGN.md` 115,
`research/bibliography.md` 180, and seven `research/findings/*.md` with one or
two each. This matches the convention every earlier package recorded, which is
that em dashes were removed from files that package authored or edited and
inherited documents were left as they were. `research/bibliography.md` is
citation text, where replacing a dash inside a quoted title or a page range would
falsify the citation. Left alone deliberately, and reported rather than quietly
carried.
