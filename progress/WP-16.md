# WP-16: correcting the stale plasmid limitation note in PROGRESS.md

A small documentation package. It changes two markdown files and nothing else.

## The finding

`PROGRESS.md` carries a section titled "Open limitation for the operator: plasmid
gold cases and the new runner". It states that the plasmid gold set "does NOT run
through WP-09's new multi-capability runner, so it is not yet subject to the three
assertions in specification 9.3", and that closing the gap "is real work and it is
not started". Its consequence paragraph adds that the claim "all four capabilities
correctly reject every known-bad case via the expected check_id" holds "for
plasmid only under the weaker assertion its own harness makes".

## Why it was stale

WP-12 did that work. Per `progress/WP-12.md`, it added `PlasmidValidator` as an
adapter to the section 5.3 validator interface, registered it on `PLASMID_SPEC`,
and converted the 88 curated plasmid records into the new case format under
`tests/gold/plasmid/` (25 Tier A, 11 Tier B, 52 known-bad). From then on plasmid
runs through the same runner as the other three capabilities and is subject to all
three section 9.3 assertions: expected overall severity, the named check reporting
that severity, and no unexpected FAIL. The note was written before WP-12 and was
never revisited, so a reader of `PROGRESS.md` alone would believe a gap that no
longer exists.

## What was measured

The command was `make eval-capabilities`, run by the operator. Its output:

```
[plasmid]
  all cases   88/88  accuracy 1.000
  known-good  36/36  accuracy 1.000
    tier A    25/25  accuracy 1.000
    tier B    11/11  accuracy 1.000
  known-bad   52/52  accuracy 1.000

TOTAL 179/179 cases agree (accuracy 1.000); 0 disagreement(s)
```

These figures are copied from that run. They were not recomputed by hand and the
command was not re-run for this package. They agree with the counts WP-12
recorded.

## The decision: append, do not edit

The build record in `PROGRESS.md` is append only. The point of that rule is that a
reader can see what was believed at each moment, including what turned out to be
wrong. Rewriting the stale paragraph would erase the fact that the limitation was
real when it was written, and would make the record look as though it had always
said the right thing. So the original paragraphs are untouched, and a block headed
"CORRECTION, superseded by WP-12" was appended immediately after the end of that
section, before the next heading. It says what WP-12 did, gives the measured
figures, and states that the consequence paragraph no longer applies: the claim now
holds for all four capabilities under the new runner.

A short summary section for this package was also appended at the end of
`PROGRESS.md`, matching how WP-13 to WP-15 are summarised there.

## What was deliberately not done

* No other `PROGRESS.md` text was changed. Every pre-existing sentence is where it
  was.
* No code, test or data file was touched. This package is markdown only.
* The `make eval-capabilities` numbers were taken from a run, not recomputed by
  hand, and no other figure was introduced.
* Nothing was claimed beyond what `progress/WP-12.md` records.

## Verification

`python -m pytest -q` was run as a gate to confirm the tree is green; the result
is recorded in the commit report. `make eval-capabilities` and `make eval-check`
were not re-run here because nothing they read was changed.
