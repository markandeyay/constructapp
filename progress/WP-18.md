## What changed, in one line

`make lint` now runs ruff 0.16.10 against the whole tree with a rule set that
finds defects and ignores formatting, and 29 of the 32 findings it reported are
fixed.

## The rule set, and why each exclusion

The rule set was picked by running candidate sets over the tree and reading the
findings, not by taste. The brief it had to satisfy: catch real problems, leave
pure formatting preference out, and do not pick a line length that fights a
codebase which writes long explanatory comments on purpose.

```toml
target-version = "py311"
line-length = 120

[lint]
select = ["F", "E401", "E7", "E9", "W605", "B", "A"]
ignore = ["B905"]
```

What it catches: unused imports and variables (`F401`, `F841`), undefined names
(`F821`), f-strings with no placeholders (`F541`), bare `except:` (`E722`, in
`E7`), invalid string escapes (`W605`), mutable default arguments and the rest
of bugbear (`B`), and builtin shadowing (`A`). Syntax and IO errors via `E9`.

The exclusions are the load bearing part, and each is recorded in `ruff.toml`
with its measured count rather than asserted:

* **`E501`, line length: not selected.** Measured over 254 tracked Python files
  and 60,955 lines, the 95th percentile line is 92 characters, the 99th is 111,
  the longest is 295, and 274 lines exceed 120. The long lines are deliberate
  single line strings, data tables and prose. `line-length = 120` is therefore
  informational only. Picking any number here would have been the formatting
  fight the brief said to avoid, so the rule is simply off.
* **`BLE001`, blind `except Exception`: not selected.** 27 findings. The design
  requires broad catches at evaluation boundaries so that a check reports
  UNKNOWN with a reason instead of crashing, which is specification section 3.3
  constraint 4. The rule fights the architecture rather than finding a defect in
  it, and clearing it would have meant 27 targeted `noqa` comments on
  deliberate handlers, which is the blanket silencing this pass forbids.
  `E722`, a genuine bare `except:`, reports **zero**, so the thing the brief
  actually named is already absent from the tree.
* **`PLC0415`, import outside top level: not selected.** 110 findings, on lazy
  local imports the codebase uses on purpose and documents, for example
  `coerce_design` importing the composer inside the function so that
  `packages.validation.aav` carries no import time dependency on
  `packages.generation.aav`.
* **`E402`, import not at top of file: not selected.** 46 findings, on
  deliberate conditional and path setup imports. Stylistic.
* **`B905`, `zip` without `strict`: ignored.** 21 findings, none fixable without
  either changing behaviour, since `strict=True` can raise, or adding a no op
  annotation.
* **`RUF100`, unused `noqa`: not selected, and recorded as a known gap.** This
  one is worth stating because it is the rule that prevents `noqa` rot and it
  would be good to have. The tree carries 9 `# noqa` comments for `BLE001`,
  `PLC0415` and `E402`, each with a written reason. It was verified empirically
  that RUF100 flags all 9 as non enabled **even when those codes are listed
  under `ignore`**, so turning it on would require deleting 9 comments that
  carry real reasoning, and one of the 9 sits in a file this pass was not
  allowed to touch. It becomes available the day `BLE`, `PLC0415` and `E402` are
  taken on, and not before.

Two details worth recording about the tree, because they shaped the choices:
`BLE001` and `PLC0415` already appear in existing `noqa` comments, so the
authors were already thinking in these rule names, and double quotes dominate
string literals 19,673 to 403, so no quote style rule was needed.

## The pin, and a deliberate deviation from house style

`requirements.txt` now carries `ruff==0.16.10`, in its alphabetical position
between `requests` and `starlette`.

Every other line in that file uses a lower bound with an exclusive next major
cap, `>=X.Y,<N+1`. The `==` here is deliberate and is the one case where that
style is wrong: ruff's rule behaviour changes between releases, so a floating
linter version makes `make lint` non deterministic across machines and across
time. A gate has to pin the exact version whose findings were triaged, which is
the version this work package triaged. No comment was added to the file, which
has none and is machine read; the reasoning lives here.

`ruff.toml` is at the repository root rather than in a `pyproject.toml`, because
no `pyproject.toml` exists in this repo and creating one could change packaging
and other tooling behaviour. `.gitignore` already ignored `.ruff_cache/`.

## Findings, before and after

Measured with the committed config. `python -m ruff check .` and the same config
over `git ls-files '*.py'` both report the same count, so `.` picks up nothing
extra and no `exclude` was added.

| Rule | Before | After | What it was |
|---|---|---|---|
| `F401` unused import | 11 | **1** | dead imports |
| `F541` f-string, no placeholder | 7 | **0** | `f"capability=aav"` and similar |
| `F821` undefined name | 3 | **0** | `Mapping` never imported |
| `F841` unused variable | 3 | **0** | dead bindings |
| `B023` loop variable not bound | 2 | **0** | late binding closure |
| `B017` blind exception in a test | 1 | **0** | `pytest.raises(Exception)` |
| `A002` builtin shadowing argument | 4 | **1** | public `format=` keyword |
| `B035` static key dict comprehension | 1 | **1** | benign, see below |
| **Total** | **32** | **3** | |

The 3 remaining are all in two files this package was not permitted to edit,
because another worker owned them and was editing them concurrently. They are
reported rather than worked around, and no `exclude` or `per-file-ignores`
entry was added to hide them. `make lint` therefore exits non zero today, on
exactly these:

* `services/api/app.py:26` `F401`, `JobQueue` imported and unused. Verified
  genuinely unused: nothing in the tree imports `JobQueue` from
  `services.api.app`. A one line deletion.
* `services/api/app.py:506` `A002`, `format`. This one must **not** be renamed:
  it is a FastAPI route handler parameter, so the name is the public HTTP query
  parameter `?format=genbank`. Renaming it would change the API. It needs a
  targeted `# noqa: A002` with a reason, like the three in
  `packages/application/exports.py`.
* `services/api/e2e_app.py:102` `B035`, static key `TEMPLATE_ID`. **Read before
  being called a bug, and it is not one.** The comprehension is
  `{TEMPLATE_ID: sequence for template_id in template_ids if template_id == TEMPLATE_ID}`.
  The `if` pins the loop variable to the same constant, so the static key is
  harmless and the at most one entry result is exactly what the function's
  docstring specifies. The clean fix is to key on `template_id`, which is
  behaviour identical and silences the rule.

## Files where code changed rather than config

Eighteen files, plus the `Makefile` and `requirements.txt` for the wiring and
the pin, and the new `ruff.toml`. Every change is on a line a finding named;
nothing was reformatted, reordered or renamed.

**`F401`, name removed from an import (8 files).** Before each deletion an AST
scan over every tracked Python file checked that nothing imports that name FROM
that module, so a re-export could not be broken. No hits for any of the ten.
`VectorMatch` was checked individually as the likeliest re-export: in
`retriever.py` it appeared only on the import line, every other user imports it
from `packages.retrieval.vector_store` directly, and `retriever.py` has no
`__all__`.

* `packages/data_pipeline/ingest/curated_seed.py` (`timedelta`)
* `packages/data_pipeline/parse/sequence_parser.py` (`Any`)
* `packages/generation/spike.py` (`StringIO`, whole line; `Sequence`)
* `packages/generation/training_data.py` (`defaultdict`; `field`)
* `packages/retrieval/retriever.py` (`VectorMatch`)
* `services/api/routes/_screening.py` (`block_findings`)
* `tests/retrieval/test_recommender.py` (`PlasmidRecommendation`)
* `tests/validation/test_codon.py` (`codon_adaptation_index`)

**`F541`, `f` prefix dropped (3 files).** `packages/generation/aav/export.py`,
`packages/generation/aav/layout.py`, `packages/validation/aav/checks.py`.
Applied with `ruff --fix` restricted to F541 and the diff read line by line:
only the leading `f` changed, no string content did.

**`F821`, the real defect in this set.** `packages/retrieval/eval.py` annotated
three function parameters `Mapping[str, Any]` without ever importing `Mapping`.
Nothing crashes today only because that module has
`from __future__ import annotations`, so the annotations are strings and are
never evaluated; `typing.get_type_hints` on those functions would have failed.
Fixed by adding `Mapping` to the existing `from typing import ...` line, using
`typing` rather than `collections.abc` to match the established style elsewhere
in the tree.

**`B023`, latent closure bug.** `packages/data_pipeline/ingest/genbank.py`. A
lambda inside the paging loop of `iter_accessions` closed over `retstart` and
`retmax`. It is invoked immediately within the same iteration, so the late
binding is harmless today, but the moment that call were deferred or retried the
lambda would read the wrong page bounds. Bound as lambda defaults, which is
behaviour preserving. Verified safe by reading `_with_retries`, which calls
`operation()` with no arguments.

**`B017`, a test that did not pin what it expected.**
`tests/assembly/test_constants.py` used `pytest.raises(Exception)`. Narrowed to
`dataclasses.FrozenInstanceError`, which is what assigning to a field of the
`@dataclass(frozen=True)` `Settings` actually raises. This STRENGTHENS the
assertion, which is the only direction a lint pass may move a test.

**`F841`, handled one at a time rather than as a class**, because deleting an
assignment is only safe when the right hand side is pure:

* `packages/retrieval/recommender.py`: `plasmid = item.plasmid` deleted. A plain
  attribute read of a pydantic field, no side effect, cannot raise.
* `tests/data_pipeline/parse/test_sequence_parser.py`: `record_text` deleted. A
  leftover, not a forgotten assertion: the next statement reads the same fixture
  file, so any I/O error still surfaces, and every assertion in the test uses a
  different object.
* `packages/generation/grna/designer.py`: the binding was dropped but **the call
  was kept**, as `get_nuclease(request.nuclease)`. `get_nuclease` raises
  `KeyError` naming every supported nuclease, and running it first means an
  unknown name is rejected with that message before any enumeration happens.
  Deleting the call would have changed which error a caller sees. A bare call
  whose result is discarded reads like dead code, so a comment now says it is
  called for its exception and must not be removed as a no op. That comment is
  the point of the change: without it the next reader deletes the line and
  silently alters the failure mode.

**`A002`, the only sanctioned suppressions in this pass.**
`packages/application/exports.py`, three sites, each given
`# noqa: A002 - <reason>` in the tree's existing `# noqa: CODE - reason` style.
`format` is the public keyword argument these codecs have always taken and
`validate_export_format(format)` is called with it; renaming it would break
callers, which this pass is not allowed to do. Three targeted suppressions with
written reasons, not a blanket.

## Deliberately not done

* **No formatting rule was enabled and no formatter was run.** `ruff format`
  exists and was not used. The tree's style is consistent already and
  reformatting it would have buried this diff.
* **No blanket suppression anywhere.** No bare `# noqa`, no file level
  `# ruff: noqa`, no `per-file-ignores`, and no `exclude`. Where a rule was
  wrong for this codebase it was left out of `select` with its reason written
  down, which is honest; silencing it per file would not have been.
* **No rule was dropped because it was inconvenient.** `BLE001`, `PLC0415`,
  `E402` and `B905` were dropped because fixing them would mean either changing
  behaviour or annotating a deliberate pattern 27, 110, 46 and 21 times. Every
  rule that found a real defect is enabled and every such finding this package
  was allowed to touch is fixed.
* **No CI wiring.** There is no `.github/workflows`, no pre-commit config and no
  CI of any kind in this repo, so there was nothing to wire into. `make lint` is
  the entry point and a CI step can call it when CI exists.
* **The three findings in the parent owned files were not fixed**, and no
  mechanism was added to hide them. `make lint` exits non zero until they are
  applied. The exact fix for each is above.
* **`mypy` was not added.** The tree carries 47 `# type: ignore[code]` comments,
  all with specific codes, which suggests a type checker has been run against it
  at some point, but adding one is a separate and much larger piece of work than
  a linter and was not in scope.
