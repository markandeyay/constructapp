# Synthetic Augmentation For Training Triplets

## Scope

This spec defines a conservative research-only approach for synthetic `(context, template, target)` augmentation using the curated seed plasmids in `packages/data_pipeline/ingest/curated_seed_manifest.yaml`. It does not implement augmentation, emit nucleotide sequences, or claim that any synthetic construct is experimentally validated.

The goal is to create plausible supervised examples where a real curated seed plasmid is the `template`, the `context` asks for a biologically coherent component substitution, and the `target` is a structured intended design description or edit spec that preserves vector validity. A later implementation would need exact component coordinates, source/licensing approval, validation checks, and human biology review before using any synthetic target for model fitting.

## Relationship To Existing Triplet Formatter

`research/findings/training_data_format.md` describes a safer first formatter where the `target` remains a real, source-validated plasmid and only the context/template pairing is synthesized. This document covers a second, higher-risk augmentation lane in which the target itself is synthetic.

Use this lane only for training robustness around edit reasoning, component compatibility, and goal-to-design mapping. Do not mix these examples into evaluation sets that are intended to measure recovery of real public plasmids.

Recommended artifact labeling for any future implementation:

- `target.source = "synthetic_component_substitution"`
- `target.validation_status = "unvalidated_design_spec" | "validated_in_silico" | "human_reviewed"`
- `quality_flags` must include all assumptions, such as `synthetic_target`, `requires_coordinate_validation`, `requires_promoter_review`, or `requires_marker_review`.

## Biology Basis

Synthetic substitutions are plausible only when they preserve the functional modules that make the vector usable: replication/maintenance, selection, expression or cloning cassette structure, topology, and host compatibility. Plasmid-vector classification by origin, marker, and promoter is supported by Wang et al. 2009. Bacterial plasmid propagation depends on a compatible origin and selectable marker, as described by Brown 2002 and del Solar et al. 1998. Promoter choice must match host and transcript type; Addgene's promoter guidance explicitly separates bacterial, mammalian, yeast, plant, RNA polymerase II, and RNA polymerase III contexts. Expression cassettes require coherent promoter, expressed sequence, and downstream terminator/polyA organization, as summarized by Addgene and by Khan 2013 for mammalian vectors. Reading-frame constraints matter for fusion tags and cloning joins, as Addgene's Gateway cloning guidance notes. Shuttle vectors and yeast plasmids have host-specific maintenance and selection requirements, as in Sikorski and Hieter 1989.

## General Augmentation Rule

Each synthetic triplet should be generated by changing one primary component class at a time, with optional dependent edits that are required to keep the construct valid.

Primary substitution classes:

- Promoter swap: replace a promoter with another promoter that is compatible with the same expression host and transcript type.
- Marker swap: replace a selectable marker with an alternative marker for the same selection context, while preserving bacterial propagation selection when required.
- Origin or maintenance swap: replace a replication/maintenance element only within a reviewed compatible host/vector family.
- Payload or reporter swap: replace a reporter, insert placeholder, or target payload without disrupting vector-type-specific backbone features.
- Tag swap: replace or relocate an affinity/fluorescent/epitope tag only if orientation, reading frame, linker, start/stop logic, and fusion position remain coherent.
- Host-appropriate component substitution: convert a vector within a reviewed profile boundary, such as bacterial expression to another bacterial expression configuration, or yeast shuttle LEU2 to URA3 selection while preserving bacterial propagation.

Dependent edits that may be required:

- Update context fields so the requested host, marker, promoter, payload, tag, and application match the synthetic target.
- Preserve or update terminator/polyA downstream of the affected transcript.
- Preserve or update RBS/Shine-Dalgarno or Kozak/start context for the expression host.
- Preserve reading frame and stop-codon placement for fusion tags.
- Preserve cloning-site uniqueness or flag the example as requiring restriction-site validation.
- Preserve circular topology unless the source vector profile explicitly supports linear forms.

## Validity Rules

Apply these as hard filters before emitting any future synthetic training example.

- Keep vector profile coherent. A `bacterial_cloning_vector` cannot become a mammalian expression vector through a single promoter label change; it would need a complete mammalian expression cassette and target-cell selection assumptions.
- Preserve bacterial propagation for standard engineered plasmids: a bacterial origin plus bacterial selectable marker should remain present unless the profile explicitly says otherwise.
- Do not replace an origin with a superficially similar but host-incompatible origin. pUC/pMB1/pBR322-family changes need copy-number and compatibility review; p15A substitution changes compatibility and copy-number assumptions.
- Match promoter to host and transcript. Bacterial promoters require bacterial expression context; mammalian protein-coding cassettes require RNA polymerase II promoters; shRNA/sgRNA-like small RNA designs require reviewed RNA polymerase III or vector-specific regulatory logic.
- Keep expression cassette order and strand coherent: promoter upstream of transcript, proper start context, coding sequence in intended orientation, optional tag in frame, and terminator/polyA downstream.
- Treat promoterless reporter backbones as valid when their purpose is promoter insertion or promoter testing. Do not "fix" pGL3-Basic or pGL4.10 by adding a promoter unless the context explicitly requests a promoter-bearing reporter derivative.
- Distinguish bacterial selection from experimental target-cell selection. AmpR/KanR/CmR/TetR for bacterial propagation are not substitutes for mammalian G418/NeoR, puromycin, hygromycin, or fluorescent enrichment markers without context-specific review.
- For yeast shuttle vectors, preserve bacterial propagation plus yeast maintenance/selection semantics. LEU2/URA3 marker substitutions are plausible only when the intended yeast strain background and auxotrophy are compatible.
- Preserve vector-type-specific required elements. Viral transfer, CRISPR, AAV, or lentiviral components require profile-specific rules and should not be synthesized from the current seed unless exact required elements are annotated and reviewed.
- Do not generate full nucleotide targets from generic component names. Use structured target specs until exact source sequences, coordinates, orientation, and licensing are available.
- Do not use Addgene-only sequence content or login-gated/vendor content unless legal/provenance approval explicitly allows training use.

## What To Avoid

- Avoid cross-profile leaps, such as turning pUC19 into a mammalian expression vector, pRS416 into a lentiviral transfer vector, or pGL3-Basic into a CRISPR vector.
- Avoid swaps that remove the only selectable marker for the propagation or experimental context.
- Avoid promoter swaps across host kingdoms without explicit conversion logic.
- Avoid adding high-risk or regulated payloads, toxins, virulence factors, pathogenic sequences, or sequence-of-concern material.
- Avoid exact sequence generation for proprietary or license-unclear components.
- Avoid claiming activity level, inducibility, silencing resistance, copy number, or host range unless supported by the component source and context.
- Avoid examples where the target would require unmodeled strain assumptions, such as yeast auxotrophic markers without a strain background or T7 expression without a T7 RNA polymerase host.
- Avoid examples that teach the model to ignore reading frame, start/stop codons, linkers, or tag orientation.
- Avoid evaluation leakage: synthetic examples derived from a seed plasmid should remain in the same split/leakage group as that seed and should never appear in held-out real-plasmid tests.

## Curated Seed Triplet Patterns

These examples are conceptual. `target` is intentionally a design description, not a nucleotide sequence.

### pGEX-4T-1 bacterial expression derivatives

Template: real `pGEX-4T-1`, a GST fusion bacterial expression vector with tac/lac regulation and AmpR.

Plausible triplets:

- Context: Design a bacterial GST-fusion expression vector for regulated E. coli expression using the pGEX-style backbone, but select transformants with kanamycin instead of ampicillin.
- Target: pGEX-like bacterial expression design retaining compatible E. coli origin, tac/lac-regulated GST fusion cassette, thrombin-cleavage/fusion logic, and bacterial kanamycin marker replacing AmpR after coordinate and promoter-orientation validation.
- Required checks: marker cassette must include its own bacterial promoter/terminator as needed; marker replacement must not disrupt origin, lac/tac regulation, GST, MCS, or fusion reading frame.

- Context: Design a pGEX-style bacterial expression vector with a C-terminal His tag instead of only GST-tag purification.
- Target: pGEX-like bacterial expression design retaining GST fusion or replacing the purification modality with an in-frame His tag, depending on human-approved tag strategy.
- Required checks: exact tag position, linker, protease-cleavage site, stop codon, and MCS frame require human review.

Avoid: converting pGEX into mammalian expression by replacing tac with CMV alone; using T7 expression unless the vector and context include T7-lac expression logic and a suitable host.

### pUC18/pUC19 bacterial cloning derivatives

Template: real `pUC18` or `pUC19`, high-copy bacterial cloning vectors with lacZ alpha/MCS, AmpR, and pUC/pMB1-derived origin.

Plausible triplets:

- Context: Design a pUC-family high-copy bacterial cloning vector with chloramphenicol selection while preserving blue-white screening.
- Target: pUC-like cloning design retaining pUC/pMB1 origin and lacZ alpha/MCS architecture, with AmpR replaced by a bacterial chloramphenicol-resistance cassette.
- Required checks: replacement marker must be functional in E. coli and must not disrupt lacZ alpha, MCS, or origin-control elements.

- Context: Design a pUC19-like cloning vector with the MCS orientation matching pUC18 for reverse-orientation cloning workflows.
- Target: pUC-family cloning design with the same core origin, lacZ alpha, and AmpR selection, but MCS orientation specified as the pUC18-style orientation.
- Required checks: because pUC18/pUC19 differ by MCS orientation, target coordinate handling must be circular-aware and orientation-aware.

Avoid: treating pUC18/pUC19 as expression vectors solely because lac promoter/lacZ features are present; adding a mammalian promoter without adding a complete mammalian expression cassette.

### pBR322 bacterial cloning derivatives

Template: real `pBR322`, classic pMB1-derived cloning vector with AmpR and TetR.

Plausible triplets:

- Context: Design a pBR322-derived bacterial cloning vector that keeps tetracycline selection but removes ampicillin selection for a single-marker workflow.
- Target: pBR322-like cloning design retaining pMB1-family replication/rop behavior and TetR, with AmpR removed or disabled only if removal does not disrupt known cloning sites or required backbone functions.
- Required checks: pBR322 has historically important marker-disruption cloning sites; any marker deletion must preserve intended unique-site behavior or declare a changed cloning strategy.

- Context: Design a pBR322-style vector for dual antibiotic selection but swap tetracycline resistance for chloramphenicol resistance.
- Target: pBR322-like bacterial cloning design retaining AmpR and pMB1-derived replication control, with TetR replaced by CmR.
- Required checks: insertion coordinates and promoter orientation must avoid disrupting origin/rop and AmpR.

Avoid: changing the replication origin to p15A without updating copy-number/compatibility claims and plasmid-family identity.

### pBluescript II SK(+/-) phagemid derivatives

Template: real `pBluescript II SK(+)` or `pBluescript II SK(-)`, phagemids with lacZ alpha/MCS, T7/T3 promoters, f1 origin orientation, pUC origin, and bla.

Plausible triplets:

- Context: Design a pBluescript-style phagemid for the opposite single-stranded rescue orientation while preserving the same cloning and sequencing-primer layout.
- Target: pBluescript-like phagemid retaining pUC origin, AmpR, lacZ alpha/MCS, and T7/T3 promoter flanks, with f1 origin orientation changed between SK(+) and SK(-) semantics.
- Required checks: f1 orientation and feature coordinates must be reviewed; T7/T3 annotations should remain in-vitro transcription/sequencing features unless expression context proves otherwise.

- Context: Design a pBluescript-style cloning phagemid with kanamycin bacterial selection instead of ampicillin.
- Target: pBluescript-like cloning/phagemid design retaining f1, pUC origin, lacZ alpha/MCS, and T7/T3 flanks, with bla replaced by a bacterial kanamycin marker.
- Required checks: marker swap must not disrupt phagemid rescue, lacZ alpha, or MCS features.

Avoid: classifying T7/T3 promoter flanks as evidence of bacterial protein expression without RBS/payload/expression context.

### pACYC184 low-copy bacterial cloning derivatives

Template: real `pACYC184`, low-copy p15A-origin vector with chloramphenicol and tetracycline resistance.

Plausible triplets:

- Context: Design a low-copy p15A-compatible bacterial cloning vector with kanamycin selection for co-maintenance with an ampicillin pUC plasmid.
- Target: pACYC-like low-copy cloning design retaining p15A replication compatibility, replacing one selectable marker with bacterial KanR while preserving the other marker or documented cloning site behavior.
- Required checks: marker replacement must retain p15A compatibility and avoid unsupported copy-number claims beyond the pACYC family.

- Context: Design a pACYC-style vector that keeps chloramphenicol selection but removes tetracycline-resistance selection.
- Target: pACYC-like low-copy design retaining p15A origin and CmR, with TetR removed or disabled only if no required cloning function is lost.
- Required checks: pACYC184 uses marker regions as cloning-related features; human review is needed before deleting marker sequence.

Avoid: swapping p15A to pUC/pMB1 while still calling the design pACYC-like or co-maintenance compatible.

### pEGFP-N1 mammalian reporter/fusion derivatives

Template: real `pEGFP-N1`, a CMV-driven C-terminal EGFP fusion vector with mammalian neomycin/G418 selection and bacterial kanamycin marker.

Plausible triplets:

- Context: Design a mammalian C-terminal fluorescent fusion vector like pEGFP-N1, but use mCherry instead of EGFP while retaining G418 selection.
- Target: pEGFP-N1-like mammalian expression design retaining CMV-driven C-terminal fusion architecture, mammalian NeoR/G418 selection, bacterial propagation marker, and polyA logic, with EGFP replaced by mCherry.
- Required checks: fluorescent-protein coding sequence source/license, reading frame, linker, stop codon, and fusion orientation require validation.

- Context: Design a pEGFP-N1-like mammalian expression vector with hygromycin selection instead of neomycin/G418 selection.
- Target: mammalian expression design retaining CMV promoter, C-terminal EGFP fusion cassette, bacterial propagation marker, and mammalian polyA; mammalian NeoR cassette replaced by HygR cassette.
- Required checks: do not confuse bacterial kanamycin marker with mammalian G418/NeoR selection; replacement marker must have mammalian expression control.

Avoid: swapping CMV to a bacterial promoter; replacing only the marker coding sequence without a compatible mammalian marker promoter/polyA cassette.

### pGL3-Basic and pGL4.10 luciferase reporter derivatives

Template: real `pGL3-Basic` or `pGL4.10[luc2]`, promoterless firefly/luc2 reporter vectors.

Plausible triplets:

- Context: Design a promoterless mammalian luciferase reporter backbone with hygromycin stable-selection support instead of relying only on transient reporter readout.
- Target: pGL3/pGL4-like promoterless reporter design retaining promoter-insertion site upstream of luciferase, luciferase reporter cassette, bacterial propagation module, and adding or swapping a mammalian HygR selection cassette only after review.
- Required checks: reporter backbone must remain promoterless unless the context asks for a promoter-bearing reporter; stable-selection cassette must not alter promoter-testing logic.

- Context: Design a pGL4.10-like promoterless reporter but use the older firefly luciferase reporter payload from a pGL3-style design.
- Target: promoterless luciferase reporter design retaining pGL4-like backbone assumptions while substituting reporter payload family.
- Required checks: payload substitution may change codon optimization, cryptic regulatory sites, and assay comparability; this requires human review.

Avoid: auto-adding CMV to a promoterless reporter target when the requested assay is promoter testing.

### pRS415/pRS416 yeast shuttle derivatives

Template: real `pRS415` or `pRS416`, yeast centromere shuttle vectors with LEU2 or URA3 markers.

Plausible triplets:

- Context: Design a centromeric yeast shuttle vector for a ura3 auxotrophic Saccharomyces strain using URA3 selection instead of LEU2.
- Target: pRS415-like CEN/ARS yeast shuttle design retaining bacterial propagation and centromeric yeast maintenance, with yeast LEU2 marker replaced by URA3, effectively matching pRS416-style selection semantics.
- Required checks: strain genotype and auxotrophy must be stated; marker replacement must preserve CEN/ARS and bacterial propagation.

- Context: Design a centromeric yeast shuttle vector for leu2 auxotrophic yeast selection but with a bacterial kanamycin marker instead of ampicillin.
- Target: pRS415-like yeast shuttle design retaining LEU2, CEN/ARS, and bacterial origin, with bacterial AmpR replaced by KanR.
- Required checks: bacterial marker swap must not affect yeast marker, CEN/ARS, or origin; source sequences and coordinates required.

Avoid: converting pRS vectors into yeast expression vectors unless a yeast promoter, ORF/MCS expression slot, and yeast terminator are explicitly added and reviewed.

## Split And Leakage Policy

Synthetic examples inherit the leakage group of every source seed and every substituted component source. If a synthetic target combines pEGFP-N1 with a marker cassette from another real plasmid, the example belongs to the connected leakage component of both sources. Validation and test splits should not contain synthetic targets unless the evaluation explicitly measures synthetic edit-following, not real-plasmid recovery.

Default policy:

- Training only until humans approve evaluation use.
- Same split as the template seed and component donors.
- No synthetic derivative may be used as a template for a held-out real target.
- No synthetic derivative may be considered a source-validated target.

## Minimum Target Schema

A future implementation should persist synthetic targets as structured specs rather than raw sequences at first.

```json
{
  "target_type": "synthetic_component_substitution",
  "base_template_id": "pEGFP-N1",
  "substitutions": [
    {
      "component_class": "mammalian_selectable_marker",
      "from": "NeoR/G418 cassette",
      "to": "HygR cassette",
      "source_component_id": null,
      "required_dependent_edits": ["mammalian marker promoter/polyA validation"]
    }
  ],
  "preserve": ["bacterial propagation", "CMV expression cassette", "C-terminal EGFP fusion", "circular topology"],
  "validation_requirements": ["coordinate validation", "host compatibility", "reading frame if fusion affected"],
  "human_review_required": true
}
```

## Quality Gates Before Implementation

- Build a reviewed component compatibility table for promoters, markers, origins, tags, reporters, terminators/polyA elements, and yeast markers.
- Require exact source and license status for every donor component sequence.
- Require feature coordinates and strand for both removed and inserted components.
- Run profile-aware validity checks after substitution.
- Run restriction-site, reading-frame, start-context, terminator/polyA, GC/repeat, and sequence-of-concern checks before any full-sequence target is emitted.
- Produce audit samples for human review before using synthetic examples in fine-tuning.

## Human-Review Questions

1. Are synthetic targets allowed in first-pass fine-tuning, or should they remain train-ablation artifacts until real-target triplet quality is measured?
2. Which component donor sources are approved for training use, especially fluorescent proteins, antibiotic markers, mammalian selection cassettes, and yeast markers?
3. Should marker swaps be limited to complete promoter-marker-terminator cassettes, or may coding-sequence-only replacements be permitted when the source cassette context is preserved?
4. Which promoter families are approved for broad mammalian substitutions: CMV, EF1-alpha, PGK, CAG, SV40, or only those already present in curated records?
5. For pGEX-like bacterial expression, should tag changes preserve GST and add a second tag, or may GST be replaced by His/FLAG/Strep tags?
6. For yeast shuttle vectors, which strain auxotrophies should be represented in context before LEU2/URA3/HIS3/TRP1 substitutions are considered valid?
7. What level of validation is required before full synthetic nucleotide targets are emitted: parser-only, deterministic validator, external tool review, or molecular biologist sign-off?
8. Should promoterless reporter backbones be augmented by adding promoters, or should they remain strictly promoter-insertion templates for the first synthetic lane?
