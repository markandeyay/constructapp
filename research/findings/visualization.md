# Track H - Visualization findings

## Scope
This track investigated browser-ready plasmid visualization libraries, centered on `seqviz` and practical alternatives, for rendering circular and linear annotated plasmid maps from this system's canonical `AnnotatedSequence` shape. It focused on required input data shape, feature annotations, circular/linear rendering behavior, licensing, and frontend integration implications for a Next.js application.

## What the literature/sources establish
- `seqviz` is a JavaScript DNA, RNA, and protein sequence viewer distributed through npm, and its documented install path is `npm install seqviz`; the npm package page lists version 3.10.9, TypeScript declarations, 3 dependencies, and MIT licensing metadata. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- `seqviz` can be used as a React component via `SeqViz` or as a plain JavaScript viewer via `seqviz.Viewer()`, so it can be integrated into a React/Next.js frontend while still leaving a non-React embedding route available. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- `seqviz` supports viewer modes named `linear`, `circular`, `both`, and `both_flip`; the package documentation states that `both` renders circular and linear viewers side by side, and `both_flip` reverses their order. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- `seqviz` renders annotations, primers, highlights, amino-acid translations, enzyme cut sites, and sequence search results, and user selection/click events can be returned through an `onSelection()` callback. [Source: Lattice Automation, 2025, `seqviz` GitHub README, https://github.com/Lattice-Automation/seqviz]
- The minimum `seqviz` data shape is close to `{ name, seq, annotations }`; `seq` is the sequence string, and each annotation uses 0-based start-inclusive/end-exclusive coordinates plus fields such as `name`, `direction`, `color`, and optional `type`. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- `seqviz` documentation marks direct `file` and `accession` props as deprecated and recommends parsing sequence files outside `seqviz` with `seqparse`; this means our API should provide normalized sequence JSON instead of making the frontend load GenBank/SnapGene files directly. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- `seqparse` parses GenBank, FASTA, JBEI, SnapGene, SBOL, and accession IDs to a common shape containing `name`, `type`, `seq`, and `annotations`; its annotation fields include `name`, `start`, `end`, optional `direction`, optional `color`, and optional `type`, and npm lists it as MIT licensed. [Source: Lattice Automation, 2024, `seqparse` npm package, https://www.npmjs.com/package/seqparse]
- Open Vector Editor is an open-source vector/plasmid editor component built with React and Redux, has an MIT license in the GitHub repository, and its original repository says it has moved to TeselaGen's `tg-oss` monorepo. [Source: TeselaGen, 2024, `openVectorEditor` GitHub repository, https://github.com/TeselaGen/openVectorEditor]
- Open Vector Editor exposes a `SimpleCircularOrLinearView` example with `sequenceData` containing `circular`, `sequence`, and `features`, and its documented feature coordinates are 0-based inclusive; this differs from `seqviz`'s 0-based start-inclusive/end-exclusive annotation convention. [Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor]
- Open Vector Editor's universal build can be embedded in non-React apps, but the documentation says individual components like `CircularView` and `EnzymeViewer` require React, so using it as a fine-grained map component would couple the frontend more tightly to its React/Redux model than `seqviz`. [Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor]
- CGView.js is a browser JavaScript circular genome viewing tool adapted from the Java CGView program, and its home page documents circular and linear genome views, smooth zooming, features/plots from sequence, PNG/SVG export, and npm installation via `npm install cgview`. [Source: Jason R. Grant and CGView.js team, 2025, CGView.js documentation, https://js.cgview.ca/]
- CGView.js documentation states that it can draw genomes up to 10 Mbp with thousands of features and hundreds of contigs, which makes it more genome-browser-like than the plasmid-focused `seqviz` need for ordinary synthetic plasmids. [Source: Jason R. Grant and CGView.js team, 2025, CGView.js documentation, https://js.cgview.ca/]
- CGView.js API documentation shows an initialization shape with a target element, `height`, `width`, and a `sequence` object containing either `length` or `seq`; the docs also point users to CGParse.js for converting GenBank and EMBL files into maps. [Source: Jason R. Grant and CGView.js team, 2025, CGView.js API documentation, https://js.cgview.ca/api/index.html]
- CGView.js is distributed under the Apache License 2.0 according to its API documentation. [Source: Jason R. Grant and CGView.js team, 2025, CGView.js API documentation, https://js.cgview.ca/api/index.html]
- JBrowse 2 provides embeddable React components, including `@jbrowse/react-linear-genome-view2` and `@jbrowse/react-circular-genome-view2`, and its embedded-components documentation describes these as reusable components for placing JBrowse views on a webpage. [Source: GMOD/JBrowse, 2026, JBrowse 2 embedded components documentation, https://jbrowse.org/jb2/docs/embedded_components/]
- The npm page for `@jbrowse/react-circular-genome-view` describes it as a single JBrowse 2 circular genome view React component, shows an integration shape based on `createViewState({ assembly, tracks })`, lists 22 dependencies, and lists MIT licensing. [Source: GMOD/JBrowse, 2025, `@jbrowse/react-circular-genome-view` npm package, https://www.npmjs.com/package/%40jbrowse/react-circular-genome-view]
- JBrowse 2 documentation says embedded components differ from the full JBrowse Web app because an embedded component has access to one view type, while full JBrowse Web can load all session view types and plugins; this matters if the product later needs full genome-browser workflows rather than a plasmid map widget. [Source: GMOD/JBrowse, 2026, JBrowse 2 FAQ, https://jbrowse.org/jb2/docs/faq/]
- The JBrowse 2 paper describes JBrowse 2 as a modular genome browser with embedded linear and circular React components available on npm, and states that JBrowse 2 source code is distributed under Apache License 2.0. [Source: Diesh et al., 2023, "JBrowse 2: a modular genome browser with views of synteny and structural variation", Genome Biology, https://pmc.ncbi.nlm.nih.gov/articles/PMC10108523/]
- `igv.js` is an embeddable JavaScript genome visualization component developed by the IGV team, runs in modern browsers, and is MIT licensed according to its official documentation. [Source: IGV Team, 2026, `igv.js` documentation, https://igv.org/doc/igvjs/]
- The `igv.js` quickstart creates a browser from a container div plus a configuration object defining a reference genome, locus, tracks, and related state, which is a genome-browser track model rather than a direct plasmid-map component model. [Source: IGV Team, 2026, `igv.js` quickstart, https://igv.org/doc/igvjs/QuickStart/]
- The Bioinformatics paper for `igv.js` states that the component is embeddable, runs entirely in the web browser with no backend server or preprocessing required, is installable from npm, and has MIT-licensed source code. [Source: Robinson et al., 2023, "igv.js: an embeddable JavaScript implementation of the Integrative Genomics Viewer (IGV)", Bioinformatics, https://academic.oup.com/bioinformatics/article/39/1/btac830/6958554]

## What this means for our build
- Use `seqviz` as the default Phase 4 plasmid-map renderer because Section 9.4 already names it, it supports the exact circular-plus-linear rendering requirement, and its prop model can be derived directly from our canonical `AnnotatedSequence` without introducing a genome-browser assembly/track abstraction. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Keep the backend/frontend contract normalized around our own `AnnotatedSequence` schema and add a small adapter from `{ sequence, topology, features[] }` to `seqviz` props `{ name, seq, annotations, viewer }`, because `seqviz` itself recommends parsing files outside the viewer and receiving already-parsed sequence data. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Map feature `strand` to `seqviz` `direction` where forward is `1`, reverse is `-1`, and absent/unknown is omitted; map feature `name`, `type`, and deterministic component colors to annotation fields because `seqviz` annotations accept those fields. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Preserve the internal coordinate convention from Section 12.3 and convert explicitly at adapter boundaries, because `seqviz` uses 0-based start-inclusive/end-exclusive coordinates while Open Vector Editor documents 0-based inclusive start/end coordinates. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz; Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor]
- Treat Open Vector Editor as an option for a future editable plasmid design surface rather than the initial read-only map, because it is editor-oriented and uses a larger React/Redux state model. [Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor]
- Treat CGView.js as a fallback or future high-density/export renderer when the system needs larger genome maps, rich plot tracks, or very high-resolution SVG/PNG output; for the MVP plasmid experience it is less directly aligned than `seqviz` because its documented input model centers on a CGView viewer/map API rather than the simple sequence-plus-annotations React prop shape. [Source: Jason R. Grant and CGView.js team, 2025, CGView.js documentation, https://js.cgview.ca/]
- Avoid JBrowse and `igv.js` for the first plasmid-map UI unless we later add genomic tracks, read alignments, variants, synteny, or large reference-genome browsing; both are strong genome-browser components, but their documented configuration models are heavier than needed for showing one annotated plasmid design. [Source: GMOD/JBrowse, 2026, JBrowse 2 embedded components documentation, https://jbrowse.org/jb2/docs/embedded_components/; Source: IGV Team, 2026, `igv.js` quickstart, https://igv.org/doc/igvjs/QuickStart/]
- Implement map rendering behind a frontend adapter component such as `PlasmidMapView` so the rest of the app depends on `AnnotatedSequence` rather than on `seqviz` prop names; this also leaves room to swap in CGView.js, JBrowse, or Open Vector Editor later without changing API responses. [Source: SYSTEM_DESIGN.md Section 4.3 interface-contract rule; Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Add visual regression or browser smoke tests once the frontend exists, because the selected renderer is an interactive browser component and the Phase 4 acceptance criteria depend on the rendered map being visible and correct. [Source: SYSTEM_DESIGN.md Section 9.4; Source: Lattice Automation, 2025, `seqviz` GitHub README, https://github.com/Lattice-Automation/seqviz]

## Decisions proposed
- Default renderer: `seqviz` for Phase 4 circular and linear plasmid maps. [Source: SYSTEM_DESIGN.md Section 9.4; Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Default viewer mode: use `viewer="both"` for desktop when space allows, and switch to a tabbed or stacked `viewer="circular"` / `viewer="linear"` layout on narrow screens because `seqviz` exposes those viewer modes. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Required API-to-view adapter shape: `name`, `seq`, `annotations`, `viewer`, optional `style`, and `onSelection`; compute `annotations` from `AnnotatedSequence.features` with 0-based start-inclusive/end-exclusive coordinates. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- Color policy: assign deterministic colors by feature type (`ORI`, `promoter`, `GOI`, `marker`, `MCS`, `terminator`, `other`) in the adapter layer, while allowing a feature-level override only if validated data later supplies one. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- File import/export policy: keep GenBank/FASTA/SnapGene parsing and export outside the visualizer; if frontend-side parsing is needed for user uploads, evaluate `seqparse`, but generated designs should arrive from the backend as validated `AnnotatedSequence` JSON. [Source: Lattice Automation, 2024, `seqparse` npm package, https://www.npmjs.com/package/seqparse]
- Alternative ranking for future use: Open Vector Editor for editing workflows, CGView.js for dense circular genome/plot/export workflows, JBrowse for genomic tracks and structural-variation views, and `igv.js` for alignment/variant track inspection. [Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor; Source: Jason R. Grant and CGView.js team, 2025, CGView.js documentation, https://js.cgview.ca/; Source: GMOD/JBrowse, 2026, JBrowse 2 embedded components documentation, https://jbrowse.org/jb2/docs/embedded_components/; Source: IGV Team, 2026, `igv.js` documentation, https://igv.org/doc/igvjs/]

## Open questions / conflicts
- `seqviz` documentation clearly defines simple annotation coordinates, but this pass did not verify how `seqviz` handles a circular feature that crosses the origin; before implementing the adapter, test an origin-spanning feature and decide whether to split it into two annotations. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- The latest public package metadata reviewed here shows `seqviz` 3.10.9 and the GitHub README, but package health, maintenance cadence, and compatibility with the exact future Next.js version should be rechecked at Phase 4 implementation time. [Source: Lattice Automation, 2025, `seqviz` npm package, https://www.npmjs.com/package/seqviz]
- JBrowse package metadata can show MIT licensing for individual npm packages while the JBrowse 2 paper states Apache License 2.0 for JBrowse 2 source code; this is not blocking for an MVP that does not use JBrowse, but it should be reviewed if JBrowse becomes a dependency. [Source: GMOD/JBrowse, 2025, `@jbrowse/react-circular-genome-view` npm package, https://www.npmjs.com/package/%40jbrowse/react-circular-genome-view; Source: Diesh et al., 2023, "JBrowse 2: a modular genome browser with views of synteny and structural variation", Genome Biology, https://pmc.ncbi.nlm.nih.gov/articles/PMC10108523/]
- Need a product/design decision on whether map interactivity should be read-only in MVP or include editing; `seqviz` fits read-only visualization, while Open Vector Editor is more appropriate if users must directly edit sequence/features in the browser. [Source: Lattice Automation, 2025, `seqviz` GitHub README, https://github.com/Lattice-Automation/seqviz; Source: TeselaGen, 2024, `openVectorEditor` README, https://github.com/TeselaGen/openVectorEditor]
